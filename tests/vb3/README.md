# VB3 ground-truth programs

Original programs with known declarations, for measuring what ghidra-vb3
recovers. They contain no third-party code, so they and their compiled EXEs can
be shared.

## types

`types/TYPES.MAK` declares one variable per case procedure: every VB3 scalar
type as a local, ByRef and ByVal parameter, `Static`, module-level variable,
`ReDim` array and `Static` array, plus a global, a `ReDim ... As` array, a `Form` object, event
parameters, and variables whose types only usage reveals. Each case procedure
assigns `"CASE <name>"` to the global `Mark`; `types/expected.json` lists the
storage and type each case declares.

`types/TYPES.EXE` is the program as compiled by Visual Basic 3.0 Professional
(File > Make EXE File) under Windows 98. To rebuild it, open `TYPES.MAK` in
VB3 (not included) and make the EXE; VB3 rejects `Dim` of fixed-size arrays
inside procedures, so cases use `ReDim` or `Static`. Score it with:

```bash
python3 tests/score_types.py tests/vb3/types/TYPES.EXE --vbx-dir DIR_WITH_VBRUN300
python3 -m unittest discover -s tests          # VB3_VBX_DIR=... to check event names
```

Event parameter names need `VBRUN300.DLL` (searched next to the EXE and in
`--vbx-dir`); without it they are not checked.

The report groups results by the evidence behind each type: `recorded` (the
references' control tokens), `inferred` (usage rules), `conflict`, `unknown`.
The unit test fails on any mismatch whose type was recorded.

## stmts

`stmts/STMTS.MAK` (generated by `stmts/generate.py`) uses 114 VB3 statements
and functions, one per case procedure. `stmts/STMTS.EXE` is it compiled with
VB3. `stmts/extract.py STMTS.EXE` shows the token the compiler emitted for each
case and checks its VBDIS3 keyword (95 of 106 labelled cases decode as expected;
conversions compile to `C<typ>`, and `Print #` and `LoadPicture` to generic
tokens). `stmts/expected_calls.json` lists the Win16/DOS calls each statement
should reach; `tests/test_runtime_map.py` checks `tools/vbrun_map.py` against it
when capstone, `VB3_VBX_DIR` (with `VBRUN300.DLL`) and `GHIDRA_INSTALL_DIR` are set.

## byref

`byref/BYREF.MAK` (generated by `byref/generate.py`) covers argument passing.
`temp_*` cases pass a constant to a ByRef parameter of each type; the compiler
stores it in a temporary of the parameter's type, and `byref/extract.py
BYREF.EXE` checks that each emitted token maps to that type in
`TEMP_REFERENCE_TYPES`. The other cases have one parameter under test whose type
only argument passing reveals (pass-through, chains, typed callers, constants
next to an unreferenced parameter, `ChDrive`/`Kill` operands, a `ByVal` String
DLL argument); `tests/score_types.py BYREF.EXE tests/vb3/byref/expected.json`
scores them. `byref/BYREF.EXE` is it compiled with VB3: all 11 temporaries map to
their type and all 38 parameters are recovered (2 before the ByRef rules).

## usage

`usage/USAGE.MAK` (generated by `usage/generate.py`) has variables whose type
only their use shows: `For` counters of each numeric type, element stores and
loads on local, module and global dynamic arrays of each type, array elements
passed ByRef, and parameters compared with a literal. `usage/USAGE.EXE` is it
compiled with VB3; all 40 are recovered (18 before the `For`, array element
and comparison rules) with `tests/score_types.py USAGE.EXE
tests/vb3/usage/expected.json`.
